# Goal — A node drains instead of dying, and reads its config live

Mesh goal `node-drains`, running.

## Statement

On 2026-09-23 the mini's capacity went from 3 to 6 and the go-apis org was added, and neither reached the node for an hour: the node reads capacity and resolves its orgs only at start, has no drain, and a restart kills its running claude sessions. A watcher waiting for zero sessions never saw one (planners and evaluators don't count against capacity, so the node is rarely idle), and the node was finally restarted by hand mid-session. Give mesh-cli: (1) a drain — SIGUSR1 or `mesh node drain` stops new claims, lets running sessions finish, then exits so systemd restarts it on the new binary/config; (2) capacity and the org list re-read on each tick (node.yaml and MyOrgs), so neither needs a restart; (3) `mesh node status` shows draining.

## Acceptance

Tests: a draining loop claims nothing new and exits after the last running session ends; a capacity change in node.yaml takes effect on the next tick; a newly claimed org is served on the next tick without restart. README documents swapping the binary with a drain instead of a restart.

- 2026-09-24 · item 8 · Drain is in: `SIGUSR1` or `mesh node drain` stops the node taking new work, waits for every running session to end, then exits 0 so systemd (or launchd) starts it again on the new binary and config. The full acceptance check passes. The work is in two commits on `mesh/node-drains-8`, with no Co-Authored-By trailer, as AGENTS.md says. **How it works** - **The loop** (`internal/node/loop.go`): `Loop` has `Drain()` and `Draining()`. A draining tick still heartbeats and still runs `AfterTick`, but claims no item, plan or research and starts no evaluation. `Adopt` also refuses held items while draining. `Run` returns nil once no session of any kind is left: items, planners, evaluators and research all count. It no longer waits on `Running()` alone. Each session wakes `Run` when it ends, so the node exits straight away rather than on the next tick. - **Pidfile and draining marker** (`internal/node/runstate.go`): `node start` writes `~/.mesh/node.pid` and removes it when it exits. On `SIGUSR1` it writes `~/.mesh/node.draining` and calls `loop.Drain()`, in both poll and channel mode. - **`mesh node drain`** reads the pidfile and sends that process `SIGUSR1`. It says clearly when no pidfile exists or the process in it is gone. - **`mesh node status`** prints a line for the node on this machine (running with its pid, draining, or none) and adds `,draining` to this node's row. The heartbeat has no field for it, so the draining state is known on this machine only. The platform contract is unchanged. - **Windows** has no `SIGUSR1`, so drain is behind build tags there: `drain` gives an error and the node is only stopped. The Windows build still compiles. **Choices worth knowing** - **Evaluations** of items this node already finished are not started while draining. The brief allowed them, but a failed evaluation is offered again on every tick and could keep the node from ever exiting. The item stays in `evaluating`, and the node that starts next picks it up. - **TRD wording:** this is stricter than the TRD's Drain section (merged in item 9, in mesh-specs), which lists only items, plans and research as the claims that stop. That TRD is outside this workspace, so it still needs a one-line amendment. - **Service restarts:** I checked that the service units restart on a clean exit (`Restart=always`, `KeepAlive`). **Docs** - The README has a new section, "Drain: swap the binary without a restart". It covers the mini deploy steps and notes that capacity and orgs need no drain, and the status description now mentions the new line. - AGENTS.md describes the drain, and its deploy rule now uses `mesh node drain` instead of `systemctl --user restart`. - `mesh node model` now tells you to drain the node rather than restart it. **Tests** - **`internal/node/loop_test.go`:** - A draining loop with ready items, a goal in planning and a held evaluation claims nothing, still heartbeats in both orgs, and refuses to adopt. - `Run` on a draining loop does not return while a build, a planner or an evaluator is still running, then returns nil. - A draining loop with nothing running returns at once. - **`internal/commands/drain_unix_test.go`:** - `drainNode` with a pidfile of the test's own process delivers `SIGUSR1` to the handler that `start` installs. - Once the marker is written, the status line says `draining`, and after the node stops it no longer does. - `drain` errors when there is no pidfile or the pid in it is dead. **Acceptance run:** `gofmt -l .` is empty, and `go vet ./... && go build ./... && go test -count=1 ./...` passes. I also ran `go test -race -count=3` on the node and commands packages, and it was clean.
